# Nolde Launcher

A Windows desktop launcher for community game decompilation, recompilation,
reimplementation and port projects listed in the Nolde catalog
(https://nolde.pages.dev/). It discovers projects, downloads verified public
Windows builds from GitHub Releases, installs them into a library folder, and
launches them directly without Steam, Epic or another launcher.

## Status

Version 0.2.0 adds the features listed under "What is new in 0.2". It is still a working foundation, not a finished product. See
"Known limitations" before relying on it.

## Requirements

- Windows 10 or 11, 64-bit (for the packaged build)
- Python 3.10+ (for running from source)

## Run from source

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

## Run the tests

```powershell
pip install -r requirements-dev.txt
python -m pytest tests -q
```

The suite uses fakes and never contacts the network. On Windows, the process
launch tests that use a POSIX shell script are skipped automatically.

## Build the Windows installer

```powershell
pip install -r requirements-dev.txt
.\scripts\build_installer.ps1
```

This runs the tests, builds the folder with PyInstaller, and compiles
`packaging\installer\NoldeLauncher.iss` with Inno Setup 6 into
`dist\installer\NoldeLauncher-Setup-<version>.exe`. The installer is per-user
(no administrator rights), adds a Start menu entry and an optional desktop shortcut,
and asks before deleting user data on uninstall.

**Not yet built or tested on Windows in this environment.** The script and the
installer definition are checked by tests for their structure only.

## Build the Windows executable

```powershell
pip install -r requirements-dev.txt
.\scripts\build_windows.ps1
```

This runs the tests, then builds `dist\NoldeLauncher\NoldeLauncher.exe`. The
build script and spec file were written but have **not yet been run on
Windows** in this development environment.

## Interface

The layout follows the reference launcher: a sidebar with the logo, a
"Continue" card for the last-played game, navigation, and display filters.
Library shows installed games with Play on each cover, sorting, and a menu for
folder, verify, executable and removal. Downloads separates active from
finished transfers, shows speed and time left, and offers Retry for failures.

Project pages open inside the main window (with Back), not in a new window.
Inter and Space Grotesk are bundled under the SIL OFL. The `logo.png` wordmark
is generated by `python scripts/make_logo.py`, so it stays in sync with the
font.

## How installs work

1. The catalog entry's repository is checked against the GitHub Releases API.
   Only repositories listed in the catalog are used; names are never guessed.
2. Source-code archives are ignored. Only a Windows `.zip` build asset is
   considered installable.
3. The download is streamed to a `.part` file over HTTPS from an allow-listed
   host, with redirects re-validated. If GitHub publishes a SHA-256 digest for
   the asset, it is verified before installation.
4. The ZIP is validated before extraction. Absolute paths, drive letters,
   `..` segments, symbolic links, and suspicious compression ratios are refused.
5. Files are extracted into a staging folder inside the library and moved into
   place only after success.
6. Nothing is executed during installation. The first launch of each build
   requires explicit confirmation.

## Updating Nolde Launcher

Automatic self-update is **not** implemented in this version, so the launcher
does not claim to check for updates. To update manually:

1. Download the new release archive from the release page you trust.
2. Close Nolde Launcher.
3. Replace the program files in its folder. Your settings and library are kept
   in the user-data folder (`%APPDATA%\NoldeLauncher`), not in the program
   folder.

Publish each release with a version number following semantic versioning, and
publish SHA-256 hashes next to each download.

## Known limitations

- **The live catalog URL was not fetched by the launcher during development.**
  The development sandbox cannot reach nolde.pages.dev. The schema was read
  from a manual fetch of projects.json, and the parser was tested against
  fixtures in that shape.
- **GitHub live parsing was not verified** because the development environment
  was rate-limited by the GitHub API. The release parser is covered by tests
  built from GitHub's documented response shape.
- **Pause depends on the server.** Pausing keeps the partial file and resuming
  uses HTTP byte ranges. A server that ignores ranges makes the download start
  again from zero.
- **Game updates replace the game folder.** Save files kept inside the game
  folder are replaced. The confirmation dialog warns about this.
- **Launcher updates are verified but not installed automatically.** A package
  is downloaded and its SHA-256 is checked. Installing it is manual until a
  signed installer and an official update source exist.
- **Original game files are not validated.** The launcher explains which files
  a project needs, but it does not run any project-specific file checks. Many
  projects also need a retail BIOS or disc image that the launcher does not
  provide.
- **Only GitHub Releases is supported.** GitLab-hosted projects show their
  project page, and the Download Source Resolver is designed so a GitLab
  provider can be added later.
- **Only ZIP archives are installed.** `.7z` and other formats are reported
  rather than downloaded.
- **Not every project will run.** Many projects need extra dependencies,
  specific game versions, or setup steps that are not automated.
- **Installs are not validated against a trusted hash** unless GitHub publishes
  one. Installation from unverified sources still requires the user's trust.
- **Localization:** English only. The string catalog is ready for more languages.

## Security notes

- Downloads are restricted to HTTPS and to GitHub's release-asset hosts.
- Launching uses an argument list without a shell and never elevates
  privileges.
- Windows security features and antivirus warnings are left untouched.
- Logs (`%APPDATA%\NoldeLauncher\logs\launcher.log`) record operational events
  only.


## What is new in 0.2

- **Virtualised catalog and library.** Only the cards near the visible area are
  built, so large catalogs use far less memory and start faster.
- **Motion levels.** Full, reduced (page transitions only) or off. Computers with
  four cores or fewer start with reduced. Older on/off switches are migrated.
- **Artwork disk limit.** Covers and logos are kept on disk up to a chosen size;
  the oldest files are removed first. A button clears the cache.
- **Discover sorting.** By name, recently updated, or development progress.
- **Pause and resume** for downloads.
- **Play time.** Each game records how long it has been running.
- **Game updates.** Installed games are compared with their verified source.
  "Update" reinstalls over the existing folder and keeps the play time, launch
  options and the chosen executable.
- **Launcher update check.** Reads an official manifest over HTTPS, validates it,
  and saves a verified package. The official source is not configured yet.
- **Diagnostics export.** A text report with versions, settings and recent log
  lines. The user name and home folder are removed.
- **Keyboard shortcuts.** Ctrl+F search, Esc back, F5 refresh catalog,
  Ctrl+1 to Ctrl+4 switch pages.

## Version 0.2 additions: notifications, integrity and installer

- **Windows notifications.** Installs that finish or fail, updates found, and
  verified launcher packages show a native notification through the system tray.
  Notifications are skipped while the launcher window is in use. Turn them off in
  Settings.
- **Integrity check.** After each install, a SHA-256 record of every game file is
  saved in the launcher's data folder (not inside the game). Library > Verify
  reports missing and changed files. New files are listed separately, because save
  files are normal. Games installed before this version can get a record created
  from their current files, which only detects changes made after that point.
- **Windows installer.** An Inno Setup script for a per-user installation (see
  "Build the Windows installer").
